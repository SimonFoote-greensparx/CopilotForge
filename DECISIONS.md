# Decisions

Numbered architectural and product decisions with status and rationale (design brief section 12.1). A decision of
lasting consequence is recorded here, never settled only in chat. Superseded decisions are marked, not deleted. The
"Brief" column maps each entry to the design brief's Appendix B where one applies.

| # | Brief | Decision | Status | Rationale | Date |
|---|---|---|---|---|---|
| D1 | B-D1 | The project is **CopilotForge**, hosted only at `github.com/SimonFoote-greensparx/CopilotForge`, with an independence statement in the README and NOTICE. It is a separate project from D365Forge and is never merged with it. | Accepted | The owner asked for a new project and a new repository, with D365Forge left untouched. | 2026-10-29 |
| D2 | B-D2 | Content (skills, templates, programmes, profiles, sources, documentation) under **CC BY 4.0**; code (`scripts/`, `.github/`, future website scripts) under **MIT**. Copyright "Simon Foote and the CopilotForge contributors". Credit travels in `NOTICE.md`, `CITATION.cff`, every skill's `license` and `metadata.authors`, and every template's closing credit line. Documents an organisation completes from the templates need no credit. | Accepted | Same model as D365Forge, chosen by the owner: free for any use, including commercial, while sharing or adapting requires credit. | 2026-10-29 |
| D3 | - | **UK English**, enforced by `scripts/check-uk-english.py`; Microsoft product names keep Microsoft's spelling. | Accepted | Brief language setting. | 2026-10-29 |
| D4 | B-D4 | **Simon Foote** is the sole author, maintainer and reviewer. Changes are committed **directly to `main`**. Revisit when outside contributors join (branch protection and pull requests). | Accepted | Owner's choice for the early phases. | 2026-10-29 |
| D5 | B-D3 | The runtime is **Microsoft Copilot Cowork**: one plugin archive per active department in `cowork/plugins/`, in the plugin format Cowork's Upload plugin accepts, generated deterministically with its manifests (D22). | Accepted | Brief recommends prioritising Cowork. | 2026-10-29 |
| D6 | - | Repository layout follows the brief (section 11): `departments/`, `reviewers/` (reviewer-class departments), `programmes/`, `editions/`, `archetypes/`, `templates/`, `assessments/`, `profiles/`, `sources/`, `scenarios/`, `evaluations/`, `examples/`, `docs/`, `scripts/`, `site/`. Each department folder is itself an installable plugin with generated manifest and README. | Accepted | Evolves the D365Forge `plugins/` pattern into the brief's structure without losing installability. | 2026-10-29 |
| D7 | B-D7 | Skill frontmatter keeps the open Agent Skills top-level keys (`name`, `description`, `license`, `metadata`). The brief's fields (`department`, `lifecycle`, `maturity`, `risk-tiers`, `platforms`, `edition-support`, `reviewers`, `sources`, plus `status` and `authors`) sit inside `metadata` as plain comma-separated strings. The brief's `triggers` field lives in `tests/triggers/` so prompts are tested, not just listed. `maturity` lists the archetypes a skill mainly serves. | Accepted | Copilot Cowork validates uploaded skills against the Agent Skills format; extra top-level keys or nested values risk rejection. | 2026-10-29 |
| D8 | B-D7 | Skill body sections follow the brief (section 10) in fixed order at heading level 2, with `### Starter`, `### Scale`, `### Enterprise` under Scale notes, the standard Sources paragraph, and `## Never` last. Practitioner approach is 250-650 words. Rules in `docs/STYLE-GUIDE.md`. | Accepted | Predictable schema for contributors, generators and Cowork. Never last so edition fragments can be spliced before it. | 2026-10-29 |
| D9 | - | Skill names are unique across CopilotForge and never reuse a D365Forge skill name; plugin names are `copilotforge-<department>`; the marketplace is `copilotforge`. Brief candidate names that clash are renamed (for example `readiness-assessment` became `copilot-adoption:adoption-readiness`, `raci` became `coe-raci`, `profile-intake` became `ai-profile-intake`). `data/reserved-names.toml` holds the D365Forge names; `scripts/check-separation.py` enforces the rule. | Accepted | Both libraries can be installed in the same Cowork tenant without one shadowing or renumbering the other. | 2026-10-29 |
| D10 | B-D10 | The initial flagship programme is **AI Transformation**, with adoption, Champions and the CoE as its backbone and discovery, agent factory and governance as included programmes. | Proposed - confirm | Brief recommendation. | 2026-10-29 |
| D11 | B-D11 | Reference implementations of a Copilot Champions programme and an AI Centre of Excellence, supplied by the owner, are generalised into the Champions and CoE skills and templates. **No organisation is named anywhere in the project**: not the source organisations, clients or employers. `scripts/check-safety.py` checks this using hashed names, so the check itself names no one. No attribution to the source organisations. | Accepted | Owner's instruction: keep everything generic. Brief section 20.4. | 2026-10-29 |
| D12 | B-D5 | Editions **Starter, Scale, Enterprise**, chosen by `data/tailoring-rules.yaml`: Enterprise at 2,500+ people or 4+ business units; Starter below 250 people in one business unit without high regulatory expectations; otherwise Scale. High regulatory expectations add a **formal assurance overlay** whatever the edition. Thresholds are proposed CopilotForge conventions. | Proposed - confirm | Brief section 9.1 defines the editions but not thresholds; deterministic rules make recommendations explainable and testable. | 2026-10-29 |
| D13 | B-D6 | Archetypes **Explorer, Adopter, Builder, Scaler, AI Enterprise**. Diagnosis takes the earliest stage whose exit is not met, and reports signals of later stages separately (for example `agents-emerging`). | Proposed - confirm | Prevents placing an organisation beyond a skipped foundation, while still triggering the agent route when staff are already building agents. | 2026-10-29 |
| D14 | B-D9 | The website is generated from this tree in the same way as D365Forge's: `scripts/build-site.py` writes the core pages into `site/` (checked for drift), and `scripts/build-hosting.py` builds a self-contained site in `dist/website/` and `dist/copilotforge-website.zip` for professional web hosting at **https://copilotforge.ai/**, with a page for every guide, department, skill, template and programme, a downloads area, licence texts, 404, `.htaccess`, `robots.txt` and `sitemap.xml`. The programme builder runs in the browser and `scripts/check-programme-builder.py` proves it recommends exactly what `scripts/tailor.py` does. GitHub Pages is not used. | Accepted | Owner's instruction. Closes O1. | 2026-10-29 |
| D15 | - | The catalogue holds **27** departments: the 25 in the four layers plus the two spanning capabilities (`ai-centre-of-excellence`, `organisation-tailoring`), matching the brief's Appendix A. | Accepted | Section 3 of the brief says 25; Appendix A lists 27. | 2026-10-29 |
| D16 | - | Cowork archives are stored uncompressed with fixed timestamps; skill folders hold only file types Microsoft 365 Copilot accepts (bundled data is JSON, YAML or Markdown, never TOML); at most 20 skills per plugin and 20 companion files per skill. | Accepted | Carries forward a packaging lesson learned on D365Forge. | 2026-10-29 |
